## 行为与数据边界

人工点击脱离仍是入口；旧 `WallPerchStatus.STATE_*` 编号保持不变。
新增独立任务阶段及名字：

| `detach_task_phase` | 名字 | 行为 |
| --- | --- | --- |
| 0 | NONE | 未开始 |
| 1 | ROTATING_TO_RANGE_ENTRY | 请求准入、原离墙轨迹及支撑，等待首条合格测距 |
| 2 | RANGE_HEIGHT_CONTROL | 可以仍处于 DETACH_ROTATE，锁定首帧高度后持续测距控制 |
| 3 | HANDOVER_READY | 正常 EXIT，控制仍继续；等待新鲜 POSCTL 确认 |
| 4 | FAULT | 显式异常或人工/外部模式提前接管；不记正常成功 |
| 5 | COMPLETED | 新鲜 POSCTL 确认后释放 ROS 控制 |

`range_height_feedback.py` 不依赖 ROS：按消息源时间收集姿态，优先插值；
低频姿态不能在容差内双侧夹住测距时，可在短暂等待后使用源时间最近且仍在容差内的姿态。
不会把接收距离时的任意最新姿态拿来判定缓存测距。首帧等待期间按顺序保留候选，后来的帧不能抢占。
源时间必须晚于实际脱离开始，单调推进，并通过源时间、接收时间、设备量程、姿态匹配及实际采样倾角门。
光流质量、水平开关、融合 READY、原高度误差及离墙距离均不能阻挡首帧锁定。

首帧只做一次几何修正并立即锁定目标；低通初始化为同一高度。
机体 FLU 轴定义下，默认测距轴 `(0, 0, -1)`，
`h = -distance * rotate(q, sensor_axis_body).z + rotate(q, reference_offset_body_m).z`。
偏移向量定义为“从传感器原点到选定控制参考点”，零偏移选择传感器原点，避免猜测实际尺寸。

用户确认设备为微空 **MTF-02P**、安装方向和偏移已核对，`distance` 仍是沿轴原始距离。
YAML 据[厂家手册](https://micoair.cn/zh/docs/sensors/sensors/mtf-02-02p-sensors)配置 0.02–6 m：
这是厂家在 90% 反射率/70 klux 条件下的标称范围，不作为地板回波可靠性的证明。
保留一次余弦投影；如选用其他参考点，应填入实测偏移，不能重复上游补偿。

至少两条合格新消息、足够源时间跨度后才给出速度：原始几何高度短窗口拟合斜率，再低通。
首帧速度、初始目标速度显示为无效/NaN；无快速速度时按倾角补偿的悬停前馈下限进行受限 hold，
有新鲜快速速度后平滑切入限速串级控制。积分只消费新测距和实际经过的时间；4 Hz 数据不会被 50 Hz 发布循环伪造为更多样本。
新目标、新积分与上一条实际推力在同一锁内切换，原支撑基准保持可追溯，不学习 OFFBOARD 输出为悬停值。

阶段 2、3 及已锁目标的异常延续，绕过旧 Z 反馈与 HeightContinuation 重设。
短暂失效保留目标、清积分、停止旧误差驱动，短期限内以实际输出衔接悬停前馈下限；超时进入故障，绝不回到旧 Z。
恢复后沿用目标，重新建立速度窗口。正常阶段往返不重置首帧或总预算。
姿态轨迹、水平反馈与算法、最终 mux 的姿态/推力限速、输出权及急停检查继续保留。
只在本轮新模式下，mux/模式管理器的数据门改为校验实际所需的姿态和水平字段；世界竖直反馈不再误作垂直控制依赖。
如果输入 twist 为机体系，机体 z 仍可能参与变换得到水平速度，这是原水平算法的需要。

## 稳定与交回

任务进入阶段 3 需要测距高度/速度有效且满足容差、轨迹完成、实测与实际发布姿态≤5°、角速度回稳、
水平/退墙稳定、前距及航向确认、实际输出和 OFFBOARD 权限新鲜，连续满足默认 1 秒且至少 4 条新测距。
PX4 的接管估计标志、遥控通道与原融合恢复确认是独立条件；不会将它们解释成“测距高度未到目标”。
模式管理器发布带轮次、maneuver id、源时间的独立接管就绪快照，避免与任务稳定条件形成循环等待。

阶段 3 仍输出同一个测距闭环；任一条件失效立即撤销资格、退回阶段 2。
模式服务线程在等待服务之后及 RPC 前复核资格和本轮身份。
`mode_sent` 只表示请求提交；记录请求时间，实际接收的新鲜 POSCTL 状态才确认完成。
过期/重复模式消息不能刷新资格，早于本次模式请求的 POSCTL 消息不能确认该 RPC。
异常交回或准备完成前的人工模式接管保留 FAULT 结果，急停/上锁仍停止输出。

## 配置与接口

新增参数集中在 `config/wall_perch.yaml`。默认入口 10°、工作角 15°、测距时限 0.60 s、
姿态匹配容差 0.03 s、速度窗口 0.8 s、失效额外支撑 0.30 s、总控制预算 15 s、交回等待 6 s。
高度/速度稳定门分别为 0.10 m 和 0.20 m/s。测距配置在节点启动时一次性读取、转换并校验，
保存为不可变配置；HOLD 准入、每轮实际脱离和测距闭环只读取内存，不再访问 ROS 参数服务器。
修改 YAML、launch 参数或通过 `rosparam set` 修改参数后，须重启基础程序才能生效，
同一节点的后续脱离轮次继续使用启动时配置。控制周期每次重新判断准入条件，不跨周期缓存结果。

普通 YAML 开关为 false；`wall_console_flight.launch` 的普通实飞入口启用。
有约束台架及其他入口保持原路径。
launch 支持 `detach_range_height_enabled`、`detach_range_entry_tilt_deg`、`detach_range_operating_tilt_deg`、
`detach_range_min_distance_m`、`detach_range_max_distance_m`、`detach_range_geometry_confirmed`。
后五项不传时读取 YAML，避免空的 launch 默认值覆盖设备配置。

`WallPerchStatus` 增加阶段、轮次、目标、当前值、速度有效性、首帧证据、源/接收时间、
连续稳定证据、阻挡原因、冻结参数和拒绝原因计数。
候选消息将任务阶段、轮次、测距控制标志及反馈有效性与姿态/推力原子传递到唯一输出 mux。
网页与 CSV 区分原始距离、几何高度、固定目标、未就绪速度及独立融合诊断；bag 保留原始消息与就绪快照。

这些 ROS 消息定义已经改变，运行新程序前必须重新生成消息并在规定的 `ros1_noetic` 容器编译。
后续已执行规定的 Docker `catkin_make`；没有用宿主机构建替代。

## 后续更新：人工一键定高

启动配置 `detach_range_manual_target_m` 默认 **1.5 m**，也可通过同名 launch 参数设定。
它是垂直高度的固定目标，只替换控制器目标，不投影目标数值、不覆盖实测高度、原始距离或首帧证据。
参数随节点启动配置固定；控制台在基础程序运行期间锁定配置。
修改目标参数后须重启基础程序；按“一键定高”执行既定目标不需要重启。

在阶段 2、或者尚未提交 POSCTL 模式请求的阶段 3，可手动点击“一键定高”。
须旋转轨迹完成、实际与发送姿态回平、角速度及水平速度稳定、融合恢复确认，
并具有新鲜测距/测距速度、实际侧吸输出、急停与已解锁 OFFBOARD 权限。
阶段 3 接受后撤销交回资格，回到现有 `RECOVER` / 阶段 2；不新增大状态机。
沿用原悬停支撑基准，从最后实际输出推力衔接，清积分并重新进行 0.30 秒控制混合。

如果本轮仅因测距控制总预算或交回等待超时进入 `ABORT` / `FAULT`，按钮须重新准入：
还要求新鲜有效的安全离墙间隙和原接管航向。取消、测距长期失效、时钟异常等其他故障不能用此按钮清除。
重新准入后记录原故障并作为新的人工恢复动作继续，重新采集离墙间隙证据；
达到目标后仍须通过完整稳定与 PX4 / 遥控交回检查。
新鲜 POSCTL 确认后动作阶段可完成，但 `detach_completed` / `recovery_completed` 保持 false，
`fault_recovery_completed` 为 true，避免把异常后的人工恢复记作原离墙正常成功。

每轮最多接受一次人工定高。它从人工接受时刻获得一份原配置的有限控制预算（默认 15 秒），
首帧 `lock_time` 保持不变；普通阶段往返仍不重置当前预算。
相同请求 id 重发只返回原结果，不再执行；不同 id 的重复点击也不延长预算。
所有动作保留原推力限幅、速度限幅、最终 mux 变化率与急停保护；没有自动重试。

服务 `/wall_perch/set_range_height` 使用 `SetRangeHeight.srv`，请求包含 id、maneuver id、
轮次、预期目标版本及请求 ROS 时间（0.5 秒有效）。目标来自冻结配置。
控制台 HTTP `/api/set-range-height` 经原 SSH 共享控制权通道调用，观察端或暂停反馈端不能提交。
目标版本随人工切换递增，旧版本的交回就绪、排队模式请求均失效；已发出的模式请求阻止再改目标。
状态、网页与 CSV 增加目标来源、目标版本、动作开始时间、人工请求 id、原故障及可用/阻挡原因；
操作日志同时保留实际目标与首帧记录。

## 2026-10-22：异常恢复与人工定高的竖直阻尼

快速相邻测距速度现在用于所有仍由测距支撑的脱离/恢复路径：
`DETACH_ROTATE`、`RECOVER`、`ABORT` 及 `EXIT`，包括人工目标和人工故障恢复。
此前仅正常、无故障且未改目标的路径使用快速速度；旋转超时在首帧测距前进入
`ABORT` 时，后续保高会一直使用 0.8 s 回归窗口及低通后的慢速速度，
造成方向反转时继续沿旧方向纠偏。慢速回归保留为独立稳定/交回证据。

这是已有支撑的数据源统一，不重新准入故障任务，不清除原故障，不改变已锁定目标或
悬停基准。快速速度失效仍清积分，在原 0.30 s 短时支撑预算内以已验证实际推力衔接悬停前馈下限；
持续失效锁存故障并停止产生有效支撑，不切回慢速度、旧 Z 或高度单环。
后续新鲜样本不能自动解除锁存；人工定高也不能利用早先的可重试超时原因掩盖该故障。
首个故障原因和当前快速速度失效原因分别保留。

人工定高准入还需快速速度新鲜有效。保高稳定判断同时要求快速和慢速速度都满足原速度容差，
防止慢窗口接近零但实际已反向加速时误报稳定；原交回、姿态、输出权和急停条件继续执行。
控制比例、积分、上下速度限值和推力数值限制均保持原值。

最终输出 mux 在即将执行最终限速时重新取时钟，与上一条实际发布的时间相减。
旧实现用本轮定时器开始时间减去上一轮实际发布时间，逐周期少算处理耗时，
使配置的推力变化率随 CPU 处理耗时增加而降低。仍保留 50 ms 单次预算上限、
最终发布前的新鲜度复核和原推力/姿态变化率限制，不补发停顿期间的累计变化。

最新 16:33 记录的同输入对照用于检查控制方向；记录输入和实际输出保持原样，
不能据此推算修改后的飞行高度轨迹。实际抑制波动的幅度须由新一轮受控记录确认。

## 2026-10-22：下降保护与油门控制统一测速来源

测距控制使用的速度和下降安全检查共用一个速度选择入口。已锁定并同步实际输出的
