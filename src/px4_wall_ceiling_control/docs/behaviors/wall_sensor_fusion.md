# 侧吸光流与对地测距融合参数切换（test1019）

`wall_console_flight.launch` 默认启用此功能；其他启动入口默认关闭。管理节点只处理本次运行内的参数切换，不读取旧的断电恢复记录。单独的 `wall_sensor_fusion_manager_node` 在本轮 `IDLE` 待命阶段，通过 MAVROS 原始 MAVLink 链路发送按名 `PARAM_REQUEST_READ`，匹配新收到的 `PARAM_VALUE`，异步读取飞控 `EKF2_OF_CTRL`、`EKF2_RNG_CTRL` 原值，不强制拉取整个参数表。首次进入 `WALL_HOLD` 时，在内存保存原值和本轮恢复状态，再异步把两项设为 `0`。此功能管理估计器参数，不停止原始光流、对地测距采样或日志，也不修改独立的前向和顶部雷达。翻转开始、捕获阶段不提前关闭这两项参数。

## 恢复时机与控制约束

进入 `DETACH_ROTATE` 后，用新鲜里程计姿态四元数计算实测总倾角：归一化四元数后，`acos(clamp(1 - 2*(x²+y²), -1, 1))`。角度表示机体推力轴与世界竖直方向的夹角，不是单独的俯仰角，也不是目标姿态。

向水平转动、总倾角不超过 `restore_tilt_deg`（初值 `80°`）时，请求恢复本轮保存的两项原值。进入脱离时已经不超过阈值，则立即请求。恢复请求不受水平控制的 `45°/s` 门槛限制；新鲜姿态/状态回调直接锁存满足条件的恢复意图，避免定时器延迟漏掉阈值事件。姿态在阈值附近波动不会重复开关。关闭后发生异常回正时应用同一姿态条件；新鲜飞控状态确认已上锁时，可直接恢复原值。

参数读写在一个独立工作线程中串行执行，不执行恢复记录写盘或 `fsync`，写入通过 `PARAM_SET` 与新收到的匹配 `PARAM_VALUE` 确认。关闭顺序为光流→测距，恢复顺序为测距→光流；恢复原值后经过应用缓冲，再按名读回两项参数，校验成功后才放行。等待、超时和重试不会阻塞姿态或推力输出。本次运行内的部分成功、迟到响应和断连仍保留待恢复义务；原值未知时不自动猜测或改写参数。失败限频重试并报告原因，不让飞机停在倾斜姿态等待。

关闭请求的调度与派发使用同一条件：新鲜、已连接且已解锁的飞控状态，以及新鲜 `WALL_HOLD`。退出 HOLD 后不再排入剩余关闭请求。工作线程在派发前复核授权；未发出的旧请求取消不算通信失败，不清除已有参数确认，也不启动指数退避。恢复意图不继承关闭阶段的退避，包括旧写入迟到失败或确认值不匹配，但实际在途写入必须返回后才可发出恢复请求。真实恢复失败继续退避；参数操作不再依赖磁盘保存完成。

两个原值确认恢复后，还需默认 `1.2 s` 应用缓冲，以及缓冲结束后的新光流、估计器和里程计反馈。参数就绪后，姿态恢复时间点的建立与新样本等待并行，不因最后一个传感器到达再推迟姿态时间点。仍须满足回平后的新反馈、完整光流积分区间、连续有效样本及确认时长；新融合轮次、倾角或角速度超限均重置准入。原有 `10°`、`45°/s` 和连续确认门限不变。正常回正轨迹、脱离保高逻辑、最终 POSCTL 实际确认要求保持原规则。

**参数确认和应用缓冲均不能证明实际融合已经开始。** `80°` 是通信及估计器恢复时延的标定初值，目标是在实测总倾角回到 `10°` 前恢复实际融合；它不是对“参与融合的每个样本必然在 ≤10° 采集”的硬限制。是否达到目标必须用 ULog 核实，不能把 ROS 状态当作飞控融合事实。

## 配置与恢复记录

配置位于 `config/wall_sensor_fusion.yaml`，ROS 参数命名空间为 `/wall_sensor_fusion_manager_node`。主控制台启动参数 `wall_sensor_fusion_enabled` 控制启用，`wall_sensor_fusion_restore_tilt_deg` 设置恢复角度。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `enabled` | `false`，主控制台覆盖为 `true` | 启用侧吸参数管理 |
| `restore_tilt_deg` | `80.0` | 实测总倾角恢复请求阈值 |
| `application_settle_s` | `1.2` | 原值确认后的应用缓冲 |
| `odom_timeout_s` / `status_timeout_s` / `state_timeout_s` | `0.30` / `0.60` / `1.50` | 姿态、侧吸状态和飞控状态新鲜度 |
| `request_timeout_s` | `5.0` | 参数请求超时 |
| `parameter_reply_timeout_s` / `parameter_reply_retries` | `0.60` / `2` | 单次按名参数响应等待及重试次数 |
| `retry_initial_s` / `retry_max_s` | `1.0` / `8.0` | 重试退避起点与上限 |
| `mavros_namespace` | `/mavros` | MAVROS 命名空间 |
| `vehicle_id` | 可选；使用节点默认值 | 固定飞控身份及同一设备管理进程锁 |

本轮原值和恢复意图仅保存在内存中。节点不读写旧的 `.wall_sensor_fusion/*.json`，不执行断电恢复或重启隔离等待；旧记录留在原处但不参与当前运行。节点重启后在新鲜 IDLE 状态读取飞控当前参数作为新一轮原值，不猜测重启前的设置。正常运行内仍按恢复角度恢复原值、确认 ACK、等待应用缓冲并读回核对。

同一飞控的管理进程锁位于 `/tmp/wall_sensor_fusion_<identity hash>.lock`，只用于避免多个管理节点同时写参数，不包含恢复记录、不做同步写盘。域层保留的旧磁盘日志类供历史回归测试使用，实际节点不实例化它，工作线程也不接入该日志。

## 状态和日志

`/wall_perch/sensor_fusion_status`（`WallSensorFusionStatus`）报告参数事务阶段、轮次、原值、目标值、确认值、请求/确认时间、缓冲截止、实测倾角、重试次数和原因。`confirmed_flow`、`confirmed_range` 为 `-1` 时表示未知。`parameters_restored` 表示恢复事务已结束、原值已确认；节点在应用缓冲后再次读回校验，才清除待恢复义务。`control_ready` 还要求没有未完成事务以及新鲜的飞控和侧吸状态；消费者仍须检查新的传感器与估计器数据。这两个字段都不表示实际融合。

控制台 HTTP 状态键为 `wall_sensor_fusion`，ROS 时间序列化为秒数；页面明确标注“参数切换”，反馈过期时清除当前确认展示。详情默认收起，分别展示两项参数的原值、请求值和确认值。

ROS bag 保留完整状态话题及原始光流。`signals.csv` 保存 `wall_sensor_fusion_*` 字段、消息年龄与头时间；请求、确认和缓冲截止时间列以 `_s` 结尾。`events.log` 仅记录事务变化；倾角和发布头时间的连续变化不产生重复事件。

`/wall_perch/sensor_fusion_operation` 和 ROS 节点日志提供单次操作诊断，包括 token、revision、目标值、排队/链路耗时及是否取消。实际节点不再产生 `persist_s`、`clear_s` 或 `persisting`、`clearing` 阶段；`wire_s` 表示飞控参数通信耗时。

## 台架验收与标定

1. 对齐 ROS 与 PX4 时间，画出实测总倾角、状态阶段、两项请求及确认值、请求/确认时间、缓冲截止，以及水平控制恢复与模式交接时刻。
2. 首次 HOLD 应只启动一轮关闭；正常脱离、已低于 `80°` 的脱离起点和异常回正均应恢复原值。本次运行中的重连、一个参数成功而另一个失败、迟到响应不得丢失内存恢复状态或提前允许模式交接；节点重启不再恢复上一轮状态。
3. 在 ULog 中独立确认光流融合、测距高度融合和测距地形融合。按当前固件实际记录的字段检查光流 aid source、`estimator_aid_src_rng_hgt`、高度融合状态，以及 `rng_terrain` 对应的地形状态；测距地形生效不等于测距高度或光流生效。不得仅凭原始传感器有数据、质量正常或 ROS `estimator_status` 判定正在融合。
4. 逐样本检查 aid source 的样本时间、`fused` / `time_last_fuse` 和状态标志变化；字段可能重置，不能只用整段最大时间或单个瞬时标志判断恢复点。将真正参与融合的数据时刻与相应实测姿态对齐，同时标出回正越过 `10°` 的时刻。
5. 若到达 `10°` 时还未恢复融合，先分清服务确认延迟、光流质量、对地测距有效性、一致性检查和估计器内部等待，再调整提前角度。不能用放宽估计器保护替代排查。参数原值本来关闭的来源，恢复仍保持关闭，不宣称该来源恢复融合。

本地回归测试不执行飞行命令。程序修改后必须在现有 `ros1_noetic` 容器中执行仓库规定的 `catkin_make`；只在地面且飞控状态已确认上锁时重启整条程序加载消息定义。台架与实飞融合时序验证需单独记录，不能以编译或单元测试替代。
