# test1019 翻转结束保持与 CH12 确认交回

2026-10-26，侧吸正常脱离流程。

1. 从规定的飞手模式起飞后，第一次拨 CH12：启动侧吸。
2. WALL_HOLD 后第二次拨 CH12：请求脱离翻转。
3. 脱离轨迹完成、实测俯仰非负且总倾角严格小于10°时，捕获实际姿态四元数为固定目标。
4. 在 RECOVER / EXIT 中持续保持这个目标。关闭悬停基准渐变、水平速度姿态修正及遥控器姿态微调；继续原有高度反馈推力控制和输出连续性限制。
5. 未再次拨 CH12 时不申请正常 POSCTL 交回。姿态稳定后可以进入 EXIT，但 EXIT 在这里表示保持并等待交接，不代表已经释放控制。
6. 翻转结束后再次拨 CH12，记录本轮交回确认。即使其他条件暂未满足也保留该确认，条件满足后请求 POSCTL；直到新鲜飞控模式反馈确认才结束 ROS 控制。

翻转期间拨动 CH12 不预存交回确认。CH12 必须先稳定回低位，再稳定拨高，单次拨动不重复触发。确认时间必须晚于本轮翻转开始时间，且携带它的操作意图必须新鲜、有效且仍选择侧吸。新周期、取消、解除意图、正常交接或未解锁时清除确认。模式请求线程等待服务后会重新检查确认及原有交接条件。

交回保留原有姿态和角速度稳定判据、遥控有效性、飞控估计、融合恢复、输出权限及新鲜度检查。固定姿态目标不等于固定位置，带倾角的固定目标可能导致水平漂移。本修改不承诺位置保持。姿态输出仍受连续性、倾角和安全限制，因此捕获瞬间可能需要短暂平滑跟踪，不能保证实际姿态完全不动。

正常有效测距保持不因没有CH12确认而超时自动交回；反馈丢失、急停、模式外部切换和其他异常仍执行现有保护。网页主动接管和飞手独立模式开关仍可按原有路径处理。负俯仰翻转结束的降落保护、非捕获恢复及吸顶流程保持原逻辑。

本修改新增 OperatorCommand.pilot_handover_request_time 字段，必须使用同一次 Docker 编译后的节点，旧版消息订阅进程需重启。尚未进行实飞验证。
