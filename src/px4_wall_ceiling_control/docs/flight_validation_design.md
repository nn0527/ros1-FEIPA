# 无人机实飞验证与人机协同测试系统设计方案

日期：2026-10-03（UTC+8）  
状态：设计方案，尚未实现、标定或完成实飞验收。  
适用平台：现有 PX4 多旋翼、ROS1 Noetic、MAVROS、机载计算机、实体遥控器、Windows SSH 控制台。  
约束：不增加传感器；桥下运行；新建独立页面及 EXE，可共用旧工具的连接设置。

配套文档：[飞行控制代码开发、测试与优化闭环方案](flight_development_iteration.md)。本文规定系统行为、测试流程及验收；配套文档规定如何根据需求和证据新增、修改、替换代码并持续验证，两份文档共同作为后续开发依据。

## 1. 目标与已确认决策

本项目从已完成的台架测试进入基础飞行验证。先证明姿态目标、人工输入、控制交接可靠，再验证自主起飞、悬停和短距移动，最后另行评估贴墙、吸附及复飞。

### 1.1 首版范围（已确认，优先于后文完整路线）

首版定位为**可重复、可追溯的人工主导姿态测试系统**。实现人工主导和完全接管两种状态，允许直接选择人工主导测试，不依赖先实现程序主导。

首版交付：独立 Windows EXE 与页面、共享 SSH 连接设置、逐步引导、RC 标定和映射、姿态/推力目标限幅和平滑、地面输出抑制、完全接管、防自动重入、机载日志、每步结果与参数对比。GPS 作为只读观察项，未合格不阻止不依赖定位的人工主导项目。

第二阶段才实现程序主导、程序起飞、位置/速度控制、自动保持/降落以及程序主导到人工主导的降级。后文有关这部分的设计保留为完整路线，不属于首版交付或首版验收依赖。首版页面不提供可执行的程序主导动作，可显示“后续阶段”。

首版不实现自动调参，不允许在已解锁时修改飞行控制参数。先把问题测清楚，再扩大控制能力。

### 1.2 全路线共同决策

本方案固定以下决策，不再将不同控制语义混用：

1. 全程人工解锁，页面和机载程序不提供自动解锁。
2. 程序主导时，由程序独立生成运动目标。摇杆只监测、不混入目标；不能因摇杆偏离中位就自动转为人工主导。
3. 明确降级到人工主导后，实体遥控器输入经机载程序转换成姿态和推力目标。
4. 完全接管时，退出 OFFBOARD，遥控器直接控制 PX4；机载程序仅监测记录，不再影响控制或自动重新进入 OFFBOARD。
5. 三种控制状态均保留 PX4 姿态闭环。ROS 负责目标生成、限幅、交接和监测，不重新实现 PX4 姿态/角速度内环。
6. GPS 无效线的初版人工主导采用“摇杆控制倾角、油门控制总推力”。此前的“升降速度＋回中保高”不纳入该状态，以免同一摇杆含义变化。
7. GPS 有效线允许程序执行单项起飞、定点保持和移动；前提是融合后的位置、速度及相关估计也合格。
8. 新页面是测试管理与观察入口，实体遥控器是实时人工操纵入口。SSH 不承载逐周期控制设定值。
9. 新 EXE 不叠加在旧贴墙页面上，不复用旧页面的贴墙准入逻辑。两套控制运行实例不能同时向同一飞控输出。

本方案不将“稳定姿态”理解为“任何情况下都能救回飞机”。姿态估计、角速度反馈、动力系统和控制余量异常时，程序及人工均可能无法恢复。

## 3. 控制状态与输入所有权

全文、页面、测试记录统一使用三个名称：**程序主导、人工主导、完全接管**。不再使用“人工协同”“遥控直控”等词作为状态别名。“降级”专指程序主导转为人工主导；“完全接管”专指退出 OFFBOARD、遥控器直接控制 PX4。“程序起飞”“程序移动”是测试动作，不是额外控制状态。

### 3.1 三种状态

| 状态 | 标识 | 横滚/俯仰、航向、推力来源 | PX4 模式 |
|---|---|---|---|
| 完全接管 | `DIRECT_RC` | 遥控器直接进入 PX4；ROS 不输出有效控制目标 | 预先验证的原生遥控模式 |
| 人工主导 | `ASSISTED_RC` | RC 数据进入机载程序，经映射、限幅和平滑后输出 | OFFBOARD，姿态＋推力 |
| 程序主导 | `AUTO_TEST` | 程序的单项测试轨迹；不混合摇杆输入 | OFFBOARD，位置/速度目标 |

`OBSERVE`、`PRESTREAM`、`TRANSITION`、`FAULT` 是运行阶段，不是额外的人机分工。分别记录“请求状态”和“已确认实际状态”，不能用 UI 选择值冒充控制权。

### 3.2 遥控器配置

- 独立的 PX4 原生模式开关：直接退出 OFFBOARD；不得经 ROS 才生效。
- 人工主导请求：优先使用一个已标定的辅助通道开关；页面也可发同样的降级请求。若没有空余通道，保留页面正常降级和原生模式开关完全接管。
- 摇杆四通道及开关均读取实测映射，禁止猜测序号、正反向或中位。
- 程序主导时仍监测 RC 链路和接管开关，但不使用四根操纵轴更新飞行目标。
- 核对本机 PX4 对摇杆自动退出 OFFBOARD 的配置，使其符合“明确开关切换、不因普通摇杆动作降级”的约定。实际参数以固件版本为准。
- 急停开关独立于模式接管；停桨不是正常接管或降落手段。

### 3.3 输入语义

人工主导模式：横滚/俯仰杆对应有限倾角，回中对应水平目标；偏航杆对应受限航向变化率，回中保持最后航向目标；油门对应标定后的归一化总推力。保留倾角限幅、目标变化率和推力变化率限制。

不复用贴墙模式的“在自主姿态上叠加 RC 修正”。人工主导中，人工输入是唯一运动目标来源。回中不能被描述为水平制动，油门中位不能被描述为自动保高。

完全接管初版默认目标为 `STABILIZED`，与人工主导的直接推力语义一致。`ALTCTL` 可作为独立、显式选择并验收的接管配置；它要求相应高度估计，且油门变为升降速度语义，不按 GPS 状态在两者间偷偷切换。

## 4. 系统架构

```text
Windows FlightValidation.exe
  ├─ 新页面：项目选择、指令、准入、反馈、日志索引
  └─ 本地服务：连接设置、SSH、命令回执、遥测缓存
             │ SSH：低频命令/遥测；不发送实时摇杆设定值
             ▼
机载测试运行时
  ├─ 命令入口与唯一控制端管理
  ├─ 控制状态机及试验序列
  ├─ RC 输入适配、GPS/估计质量评估、保护监测
  ├─ 轨迹生成 / 人工姿态推力映射
  ├─ 唯一 MAVROS 设定值输出与模式请求
  └─ 持续日志与测试结果
             │
             ▼
PX4：估计器、位置/速度控制、姿态/角速度闭环、控制分配
             ▲
实体遥控器 ──┘ 原生模式开关拥有独立接管路径
```

独立启动入口命名为 `flight_validation.launch`。控制运行时与旧贴墙控制入口互斥；可共享唯一 MAVROS 连接及只读传感器源，不能共享输出所有权或同时运行两个模式管理器。

输出节点是同一时刻唯一设定值写入者。位置/速度输出和姿态/推力输出互斥，切换通过状态机进行，不由两个定时器分别竞争。RC 和控制循环在机载执行，目标发布初始设计频率 50 Hz；这是工程配置，不是已测延迟或实飞保证。

## 5. 新 EXE 与连接设置

### 5.1 独立应用

- 新产品名：`FlightValidation.exe`，独立前端资源、本地服务入口、打包脚本和图标。
- 默认仅绑定本机 `127.0.0.1:8788`；旧工具默认端口保持不变。
- 新应用运行设置与日志放在 `%LOCALAPPDATA%/FlightValidation/`，不覆盖旧工具飞行参数。
- 复用 `%LOCALAPPDATA%/WallConsole/connection.json` 中的 SSH 主机、用户、认证方式、端口、私钥、known_hosts、容器和远端工作区；忽略其中的旧页面端口字段。
- 共享连接设置采用兼容读写，保留未知字段、原子保存；修改仅用于后续重连，不在飞行中静默改变连接目标。
- 密码只驻留当前会话，不保存到配置或日志；不降低主机指纹核验要求。
- 初次启动或缺配置时打开连接设置；打开 EXE 不启动控制输出、不解锁、不起飞。

### 5.2 页面布局

顶部固定显示：目标飞控身份、实际 PX4 模式、实际控制状态、解锁状态、连接/数据年龄、当前油门语义、实体遥控链路状态。

左侧为项目列表，主区为操作步骤、准入阻塞、实时曲线、判定结果；右侧为事件与命令回执。项目按依赖开放，不提供“一键执行全部实飞”。

页面提供两个同等明确的入口：**程序主导测试**、**人工主导测试**。测试方案是操作者的选择，GPS/融合估计决定是否满足准入，不替操作者选择方案。GPS 合格也可直接选择人工主导；无需先进入程序主导再降级。人工主导不以程序主导测试通过为前置条件，但仍需完成共用的基础检查、接管及姿态基线验证。

以上为第二阶段完整页面；首版仅开放人工主导测试及共用检查、完全接管和结果记录，程序主导入口不可执行。

每条流程均逐步引导，显示：当前步骤、测试目的、由谁操作、实体遥控器/页面具体操作、预期反馈、准入条件、观测指标、判定条件、当前结果及下一步。人工实际操纵由实体遥控器完成，页面负责提示和记录，不用方向按钮代替摇杆。

页面独立显示“已选测试方案”和“实际控制状态”。程序主导测试中降级后，原测试方案仍显示程序主导，实际状态显示人工主导；不能通过偷偷更改方案使原测试看起来通过。

始终区分以下操作：

| 操作 | 含义 |
|---|---|
| 启动观察 | 连接、监测、录制，不产生飞行目标 |
| 进入人工主导 | 准入及预流完成后请求 OFFBOARD，不自动起飞 |
| 启动当前程序测试 | 执行已选单项任务；起飞必须显式单独触发 |
| 降级人工主导 | 取消自动任务，执行到人工输入的交接 |
| 完全接管 | 请求预设原生模式；同时提示实体遥控模式开关可独立使用 |
| 暂停当前自动动作 | 定位健康时制动保持；定位无效时不伪装成定点暂停 |
| 程序降落 | 仅在相关估计、场地和任务条件满足时执行 |
| 停止运行时 | 仅未解锁且无控制任务时允许；不作为空中中止按钮 |

页面不增加软件停桨按钮。实体急停状态只作显著显示及记录，避免与接管混淆。

### 5.3 命令可靠性

每条动作携带会话 ID、唯一命令 ID、参数版本和期望控制状态。机载校验并返回“拒绝/接受/执行中/已完成/失败”，记录原因。成功发出 SSH 命令、MAVROS 服务返回成功均不能代替实际飞控状态确认。

重试仅重查同一命令结果，不生成第二次动作。双击、多标签页、断网重连均不重放起飞/移动/接管请求。过期命令拒绝执行；新会话不继承上一会话未完成的动作权限。

单一操作端持有动作控制权，其余客户端只读。空中断线不自动把操作权授予另一客户端。旧贴墙运行时活动时，新应用只允许观察，不能启动第二套输出。

## 6. 状态切换及平顺交接

### 6.1 优先级

原生遥控模式切换及 PX4 故障保护 > 完全接管请求 > 故障处置 > 人工主导降级 > 普通测试指令。自动任务完成不自动开始下一项，也不自动从人工状态恢复自主控制。

### 6.2 地面进入与起飞

地面准入包括：飞控身份/版本匹配、RC 有效、姿态估计有效、输出唯一、参数配置合格、实际未起飞状态。未解锁可观察及进行拆桨测试，解锁始终人工执行。

地面预流使用专门的地面目标和抑制策略，绝不直接发送悬停推力。不能沿用只允许“已解锁空中 ALTCTL”的旧交接流程。地面预流、怠速和起飞检测必须按本机固件在 SITL/HITL 验证。

人工主导：人工解锁、启用协同后，由人工油门指挥离地，不含目标高度或自动爬升。

程序主导：通过定位及高度准入、人工解锁后，单独点击起飞；锁定初始航向，采用相对起飞地面高度的受限爬升轨迹。达到目标且速度/误差收敛才进入保持。超时不自动重复起飞。

最低起飞高度门槛不能阻止地面起飞；应采用地面、爬升、空中阶段各自的高度和净空约束。

### 6.3 AUTO_TEST → ASSISTED_RC

正常请求或明确标识的故障降级事件触发，不由普通摇杆偏转触发。立即取消原自动任务及后续轨迹，记录原因。

正常交接在有效估计下先减速，再捕获当前航向、姿态及新鲜推力参考。映射后的人工推力必须与当前输出匹配到经标定的允许差值，随后做受限过渡。页面显示油门匹配方向，不向用户暗示“任意杆位都能无扰切入”。

油门未匹配时保持为“交接中”，不得报告已进入人工主导。设定经验证的交接超时；超时按预配置故障策略处理，不能无限维持可能无效的位置控制。

定位突然失效时不能先等待定位制动成功；若姿态、RC、推力交接条件满足，可进入人工主导降级。否则请求完全接管并告警。此场景的输出连续性、下降和水平漂移风险必须独立验证，不能保证完全无扰。

交接推力参考超出许可范围时拒绝普通进入或触发故障处理，不像旧交接选项那样临时绕过硬推力限值。

### 6.4 任意 OFFBOARD → DIRECT_RC

实体模式开关直接进入 PX4，不被 ROS 的姿态收敛、油门匹配或页面权限阻塞。页面请求也不得无限等待“先恢复稳定”，但它依赖通信正常。

模式请求期间中止自主任务；只在当前反馈有效的范围内维持受限过渡输出，不延续原运动任务。检测到新鲜的非 OFFBOARD 模式后，立即释放程序输出和模式请求权，锁止自动重入。

接管成功以飞控实际模式及输出所有权释放确认。RC 数据有效是必要证据，但“模式切换成功”不等于飞机已恢复稳定，页面另显示运动状态。

原生油门映射与协同推力映射应尽量一致并实测交接。紧急接管不以油门匹配为前置条件，因此仍可能有推力变化；软件不能保证任意杆位下无冲击。

### 6.5 人工状态 → AUTO_TEST

必须显式请求，重新检查定位、高度、姿态、输出流和活动边界。捕获当前局部参考，不恢复中断任务，不跳回旧航点。初版要求进入静止保持后再发新移动任务。

## 7. GPS 两条测试线及姿态底线

GPS 原始状态与控制能力分别显示：GNSS 接收状态、融合水平位置、融合水平速度、竖直估计、姿态/航向，各自独立判定。

| 条件 | 允许能力 |
|---|---|
| 水平位置/速度、竖直估计、姿态均通过准入 | 程序起飞、保持、移动；也可选择人工主导 |
| GPS 或融合水平估计不合格，但姿态、RC 等合格 | 人工主导或完全接管；禁止自主定点与短距任务 |
| 姿态/角速度估计不合格 | 不准入任一程序飞行测试；在飞故障交由预验证处置及飞手，不宣称可自稳 |
| RC 无效 | 不准入本轮人机协同飞行；在飞按预验证失联策略，不把“降级人工”当作有效措施 |

位置和速度需验证真实性，而非只有有限数值。检测数据年龄、估计有效标志、精度信息、创新/拒绝信息（本机可用时）、重置和不连续变化。odom 持续发布不代表定位可靠。

GNSS 地面静止与已知位移测试只构成初筛；需要无桨转动/移动验证、动力振动影响观察和受保护飞行验证，不能用一次静态通过永久解锁自主能力。

航向保持采用当前有效估计下的捕获参考，不要求指向正北。磁干扰或航向跳变单独处理，GPS 合格不能替代航向验收。

### 7.1 降级依据：反馈有效性与控制收敛分别判断

程序主导的自动降级依据不是单独的“GPS 高度、水平速度”。需要检查飞控融合后的水平位置、水平速度、高度、竖直速度，以及当前任务的控制误差。高度反馈不等于 GPS 高度，实际来源和融合方式以飞控配置为准；不允许把 GPS 高度直接当作起飞相对高度。

两类判断严格分开：

- **反馈有效性**：样本是否新鲜、有限，估计有效标志和质量是否合格，是否出现重置、跳变或不一致。反馈无效时，不能再依据该反馈宣称控制已经收敛。
- **控制收敛**：反馈有效时，实测运动是否跟踪当前目标，并在该阶段规定的时间内达到误差与速度容差。移动时要求速度跟踪目标，不要求速度始终为零；制动/保持时才要求速度进入零附近的容差。

### 7.2 触发与处置规则

| 检查结果 | 程序主导的处理 | 是否降级 |
|---|---|---|
| 尚未进入程序主导，所需反馈不合格 | 拒绝进入，显示缺失项 | 不属于降级 |
| 反馈有效，轨迹正在正常跟踪，但尚未达到最终位置/高度 | 在阶段时限及安全边界内继续 | 否 |
| 质量短暂下降但未触及已标定失效门槛 | 告警、持续监测，禁止扩大测试范围 | 不因单次轻微波动立即降级 |
| 任务必需的水平位置/速度或高度/竖直速度确认失效 | 终止任务，触发降级事件，不继续依赖失效反馈 | 人工主导准入满足时降级 |
| 反馈有效，但跟踪误差持续超限、振荡不衰减，或阶段超时仍未收敛 | 终止任务，记录控制失败，触发降级事件 | 人工主导准入满足时降级 |
| 位置、速度或高度触及硬安全边界 | 立即终止测试并触发故障处置，不等待普通收敛超时 | 按剩余控制能力降级或请求完全接管 |
| 姿态/角速度反馈失效，或机载控制链路故障 | 不把继续使用同一程序视为可靠降级；告警并走完全接管/PX4 故障保护路径 | 不直接宣称人工主导可用 |
| 实体开关或页面明确请求降级 | 无需等到反馈失效或控制不收敛，立即取消任务并执行交接 | 是，按交接条件完成 |

姿态跟踪误差超限需要同时检查姿态反馈和控制链路：若原因不明或底层控制已异常，切为人工主导不保证改善，应走故障处置。不能将所有失控现象统一归类为 GPS 问题。

轻微质量波动使用经标定的持续时间和回差；明确无效、过期或硬越界不得等待同一缓冲时间。质量门槛、误差门槛、稳定保持时间、阶段超时和硬安全边界分别配置，不共用一个“GPS 有效”布尔值。

### 7.3 降级完成的条件

触发降级与完成降级不是同一件事。进入人工主导前仍需 RC 输入有效、姿态/角速度反馈有效、机载输出链路健康，并完成第 6 节的姿态与推力交接。反馈失效时不能无限等待自动制动或保持成功。

页面分别显示“降级原因”“交接中”“人工主导已生效”。交接失败按故障策略请求完全接管；请求已发出不等于接管已完成。遥控失联时，人工主导和完全接管都不能作为已可用的人工兜底，必须执行预验证的 PX4 失联策略。

降级后即使 GPS/估计重新合格，也不自动回到程序主导，须由操作者显式请求并重新准入。

## 8. 故障与失联处理

以下为必须实现并验证的决策，不预设一个故障动作适用于所有反馈失效。

| 事件 | 处置 |
|---|---|
| 普通摇杆变化，仍处于程序主导 | 仅记录，不改自主目标、不切状态 |
| 人工主导降级请求 | 取消任务，按第 6 节交接；失败明确报告 |
| 融合定位退化 | 禁止新自主动作，触发故障降级；仅在其准入满足时进入人工主导，否则请求完全接管 |
| 遥控输入过期/接收机失联 | 禁止继续使用最后杆值；不进入人工主导；交给预验证的 PX4 失联/退出策略 |
| 机载进程停止或设定值中断 | PX4 OFFBOARD 失联保护；实体模式接管独立可用 |
| 姿态异常、误差/角速度超限 | 停止测试推进，告警并按已验证故障路径请求接管；不以突发固定水平目标保证恢复 |
| SSH/页面失联 | 不影响 RC 与机载循环；AUTO_TEST 在定位健康时减速保持，至已配置期限后降落；定位不健康则走定位故障路径。ASSISTED_RC 在 RC 健康时继续人工主导 |
| 飞控模式被人工切走 | 释放输出，停止模式请求，锁止自动重入 |
| PX4 链路失联 | 显示实际状态未知，不冒称已接管；飞控自身保护及实体遥控路径承担处置 |
| 地面急停触发或解除 | 清除任务；解除后也不恢复动作、不自动解锁 |

SSH 失联保持时长、降落条件及 PX4 RC/OFFBOARD 失联动作必须在飞行前配置和验证。桥下不能无审查地沿用自动返航爬升策略。若无可落地空间或相关估计不足，不能把“自动降落”作为已具备的安全结果，试验准入应阻塞。

安全超时使用单调时钟；样本接收年龄与源时间戳分别记录。检测陈旧值重复发送、时间倒退和估计重置，不能只检查消息抵达频率。

## 9. 台架旁路和参数审查

### 9.1 不做“全量开放”一键恢复

建立有效配置快照，覆盖 YAML、launch、运行时覆盖及飞控参数。每条规则归类为“通用飞行必需”“仅某阶段必需”“台架专用”“当前任务无关”。新基础飞行模式不启动贴墙决策，不受无关前/上测距准入阻塞；这不等于削弱贴墙阶段保护。

| 现有项 | 审查与处理 |
|---|---|
| `require_min_altitude` | 贴墙空中准入恢复；基础起飞使用阶段化高度约束，不照搬 0.30 m |
| `bench_wait_for_ranges` | 实飞不得启用；拆解它对传感器、下降速度、脱离高度反馈及恢复判断的影响 |
| 恢复阶段顶部测距 | 光束转离墙后可能失效；后续贴墙方案按几何及阶段重新设计，不能一律强制或一律关闭 |
| `require_armed` / 连接 / OFFBOARD | 按地面预流和正式控制阶段分别要求；正式输出必须由正确状态授权 |
| RC 校准及新鲜度 | 两条线均需有效，程序主导也需接管能力 |
| 悬停推力 0.45、接近推力 0.47、推力上限等 | 旧实验初值不是新系统的实飞标定值 |
| 交接跟随飞控推力 | 不允许为“无扰”绕过硬限制；超界走拒绝或故障路径 |
| 翻转/接触角速度及推力倍数 | 不能作为基础水平飞行限值 |
| 机构反馈 ACK、PIN、贴墙自动状态迁移 | 本轮不启用；后续专项审查，不随 GPS 合格解锁 |

### 9.2 标定与配置准入

每个飞行参数记录：单位、作用状态、初始来源、测量方法、验证日期、机体/载荷/电池条件和证据文件。关键参数缺失或未合格时只允许观察、仿真及拆桨测试。

| 参数组 | 确定方法 | 通过前禁止事项 |
|---|---|---|
| RC 通道、正反向、端点、中位、死区 | 拆桨逐通道采样，确认接收机失联表现 | 任何协同飞行 |
| 人工推力映射及接管差值 | 对照 PX4 油门曲线、反馈和受保护动力试验 | 空中推力交接 |
| 悬停推力及可用余量 | 当前整机载荷、电池条件下稳定飞行 ULog；不能由拆桨电机输出反推 | 姿态推力协同实飞 |
| 倾角、目标变化率、角速度与跟踪误差门槛 | 先 PX4 基线，再仿真、受保护小幅响应逐级确认 | 扩大动作范围 |
| 数据超时/交接超时 | 实测频率、尾部延迟及连续丢样；再做故障注入 | 以放宽超时掩盖链路问题 |
| GNSS/融合精度、漂移、跳变门槛 | 目标场地静态、已知位移、受保护动态数据 | 自主位置/速度测试 |
| 相对高度、速度、距离和停止余量 | 按场地净空、估计误差、延迟、已测制动距离确定 | 指定距离自动移动 |
| 失联动作、落地检测、完全接管模式 | 按实际 PX4 固件/参数，在仿真及拆桨验证 | 无故障处置依据的实飞 |

不在文档中虚构通用安全高度、距离、推力或角度。实现时提供有单位的必填飞行配置和独立仿真配置；不能用仿真默认值直接通过实飞准入。

## 10. 新接口与实现边界

建议新增独立命名空间 `/flight_validation`，不修改旧 `AttachmentControlCandidate` 的 wire contract，避免破坏既有贴墙节点。

| 接口 | 最小内容 |
|---|---|
| 命令服务/命令入口 | session_id、command_id、expected_state、action、参数版本、动作参数；返回接受/拒绝及原因 |
| 控制状态 | 请求/实际状态、运行阶段、实际 PX4 模式、活动任务、输出类型、转换原因、进入时间 |
| 健康状态 | RC、姿态、航向、位置、速度、高度、数据年龄、估计有效性、准入阻塞 |
| 测试状态 | 项目 ID、阶段、目标/实测、指标、通过/失败/中止/未知、证据索引 |
| 控制候选（机载内部） | 唯一来源、有效期、输出类型、ENU 位置/速度/yaw 或 ENU/FLU 姿态＋推力 |

使用明确 ROS 消息和服务类型，机载统一校验有限值、范围、过期、状态适用性。ROS 侧采用 ENU/FLU；MAVROS 完成对应 PX4 坐标转换。用已知方向测试确认，避免转换两次。

位置控制使用有效的位置目标及平滑轨迹；速度为轨迹前馈或独立速度控制时需设置正确 type mask。人工主导使用姿态＋推力，禁止同一周期同时激活两个冲突控制路径。

状态和日志版本化。修改新接口后，本机与机载需要部署匹配版本；握手不匹配只读，不接受动作。

## 11. 分阶段测试流程与放行规则

### 11.1 每次会话通用流程

打开 EXE → 核对目标与连接 → 只读检查及日志启动 → 选择本次项目/有效参数 → 检查准入 → 人工解锁（仅需要时）→ 显式执行单项 → 观察结果 → 交还遥控或降落 → 人工确认上锁 → 封存结果。

地面软件项目与实飞项目明显区分。通过结果绑定固件、代码、参数和硬件配置；相关配置变化使依赖项目失效。实飞不自动串关，人工中止不记为失败也不记为通过。

#### 11.1.1 两条页面引导流程

共用准备流程：连接与版本检查 → 日志及参数检查 → RC 方向/开关核对 → 姿态与控制链路检查 → 接管能力检查。已取得的合格证据可按版本与有效期复用，无需每次重做全部历史试验，但本次会话数据新鲜度、实际模式及 RC 状态必须重新检查。

| 方案 | 页面依次引导的飞行步骤 | 定位要求 |
|---|---|---|
| 程序主导测试 | 定位准入 → 人工解锁 → 单独触发程序起飞 → 姿态/航向与高度/位置保持 → 单方向移动 → 制动保持 → 降落/完全接管 → 上锁与结果汇总 | 必需融合估计持续有效；不合格时说明原因并禁止启动 |
| 人工主导测试 | 人工主导准入 → 人工解锁与进入人工主导 → 人工油门起飞 → 姿态/航向响应观察 → 单轴倾角输入与回中 → 人工升降推力响应 → 完全接管验证 → 人工降落 → 上锁与结果汇总 | 不要求 GPS 合格；不使用无效位置/高度数值作通过判据 |

人工主导的“姿态保持/回中”只评价姿态目标跟踪，不表示定点或保高。GPS 评估可以在该方案内作为观察项目运行，其不合格不阻塞不依赖定位的项目；只有无法取得的相关指标标记为不可评价。

步骤顺序是引导顺序，不是自动执行序列。飞行中的等待、指令空档和结果展示期间，机载控制继续按当前状态运行；页面等待“下一步”不能导致设定值流中断。

#### 11.1.2 每步结果与证据

每步执行状态统一为：`未开始 / 条件未满足 / 等待人工操作 / 执行中 / 等待现场确认 / 已结束`。已结束的结果统一为：`通过 / 失败 / 中止 / 无法判定`。操作回执、执行状态、测试结果分别保存，不能互相替代。

- 通过：配置的观测窗口完整、有效数据满足门槛，且该项目要求的现场确认完成。
- 失败：有效证据显示超限、不收敛、动作方向错误或违反该项要求，给出失败时刻和指标。
- 中止：操作者停止、非计划降级或完全接管使原步骤未完成；记录原因。若此前已明确违反门槛，保留失败，不用中止覆盖失败。
- 无法判定：数据缺失、时间未对齐或现场现象无法确认，不能自动记通过。若数据失效本身是该步骤的失败条件，则应记失败。

页面给出“实测值 / 门槛 / 持续时间 / 判定原因 / 证据链接”，而不只给红绿灯。离地、实际水平漂移、环境净空等现有传感器不能可靠独立确认的现象，由现场人员确认并单独标记为人工证据；不允许人工确认覆盖程序已发现的硬失败。

每次重试创建新的 attempt ID，保留前次结果。未执行步骤不记失败，不因整个会话结束自动记通过。下一步仅在依赖满足后开放，完全接管入口始终不受普通测试依赖阻塞。

#### 11.1.3 程序主导测试中发生降级

1. 机载端触发并记录降级原因，取消当前程序任务，冻结该步骤原始目标和已采集指标；页面不继续提示执行后续自动动作。
2. 原步骤按证据记失败或中止；显示“正在降级”，不能提前显示人工主导已生效。
3. 确认人工主导实际生效后，页面立即提示当前摇杆含义及收尾操作；人通过实体遥控器操纵，不必等待页面同意。
4. 初版默认引导人工降落，或按需完全接管后降落。不得在空中自动续接整套人工主导测试，也不立即要求重复起飞步骤。
5. 落地上锁后保留同一会话的关联记录，操作者可以直接选择人工主导测试，重新执行该方案的本次准入。若需再次选择程序主导，须重新检查触发原因与准入，不自动恢复中断动作。

计划内的“降级验证”是例外：它的目标就是验证程序主导转人工主导。只要原因、任务取消、交接和实际状态均满足要求，该降级步骤可判通过；这不等于原起飞/移动项目通过。计划外降级不能伪装成计划内验证。

### 11.2 测试项目

首版执行顺序：T00 软件/仿真 → T01 拆桨输入 → T03 中人工主导与完全接管部分 → T04 首版故障处理 → T05 PX4 原生姿态基线 → T06 人工主导 → T07 完全接管 → T11 人工降落及重复性。T02 可并行作为只读观察；T08、T09、T10 及程序主导专属检查留到第二阶段。

T06 必须拆成独立步骤：姿态保持观察、横滚小幅输入/回中、俯仰小幅输入/回中、偏航小幅输入/回中、油门及升降响应。一次只改变一个操纵轴；不在同一步同时要求转向、平移和升降。必要的维持飞行油门调整仍需记录，不将真实飞行假设为其他输入完全不变。

| ID | 项目与条件 | 操作 | 必须验证 |
|---|---|---|---|
| T00 | 软件/仿真 | 模式状态机、输出切换、失联注入 | 无重复动作、无控制争抢、无自动重入 |
| T01 | 拆桨，连接与 RC | 逐杆、逐开关采样 | 通道/方向/语义正确；回中及失联识别正确 |
| T02 | 拆桨，GPS/融合初筛 | 选定区域静置及前后左右已知位移、停止 | 漂移、方向、速度收敛、遮挡变化、重置，不仅看卫星数 |
| T03 | 拆桨或 HITL，接管 | 程序主导摇杆变化、降级开关、原生模式开关、页面请求 | AUTO 不混杆；仅明确降级后用杆；完全接管不受 ROS 门槛阻塞 |
| T04 | 拆桨或仿真，故障 | SSH 断开、ROS 停止、RC 失联、估计失效 | 各走指定策略；页面不误报成功；恢复不重放 |
| T05 | 受保护动力试验，原生 PX4 基线 | 原生稳定模式小幅响应 | 飞控姿态能力本身合格，不把底层问题误归因于 ROS |
| T06 | 受保护动力试验，人工主导 | 人工推力离地、短时保持、单轴小输入、回中 | 姿态误差、角速度、航向、延迟、推力响应；记录水平漂移 |
| T07 | 受保护交接试验 | 人工主导→完全接管；之后显式重新进入 | 实际控制权变化、推力连续性、无重抢 |
| T08 | 定位合格，程序起飞/保持 | 人工解锁，单独触发起飞，达到目标后保持 | 高度/位置/航向误差、超时及任务完成判据 |
| T09 | 定位合格，单方向移动 | 每次单轴短距，停止后保持 | 方向、速度、超调、制动距离、姿态稳定 |
| T10 | 降级验证 | 先仿真注入定位退化，再验证健康条件下人工请求降级 | 取消旧任务、油门匹配、输出类型切换、接管锁止 |
| T11 | 降落与重复性 | 合法条件下程序/人工降落、上锁、再次独立起飞 | 无残留命令和旧参考，结果可复现 |

实飞禁止为了 T10 人为制造不可控的 GPS/RC 丢失；故障注入先在仿真/HITL/拆桨完成。受保护试验装置会改变动力学，其通过不能直接代替自由飞行验收。

GPS 无效线以 T06、T07 的人工主导可控性为目标，不要求或声称定点、精确短距和自动水平制动。GPS 有效线还需 T08、T09。进入自由飞行前仍需具备足够的人工直接操纵能力或合适试验保护；接管功能存在不能代替飞手熟练度。

### 11.3 指标与判定

- 姿态：四元数最小旋转误差、各轴角速度、航向误差、收敛时间、振荡及持续超限时间。
- 交接：请求到实际模式确认的时间、目标/实测姿态变化、推力阶跃和变化率、切换后输入响应。
- 定位：静态漂移、已知位移偏差、停止后虚假速度、数据中断及估计重置。
- 自主运动：高度/水平误差、超调、停止距离、边界余量及饱和情况。
- 链路：RC→目标、命令→确认、遥测年龄和连续缺样；不同主机时钟未同步时不能声称测得精确单程时延。

各项均使用第 9 节审批后的配置门槛。缺数据、反馈过期、日志未完整时判为“未能判定”，不能自动通过。结果必须同时满足数值门槛与实际现象检查，不因持续几秒没有异常就判稳定。

### 11.4 基线、停止条件与参数迭代

先保留 PX4 原生稳定模式基线，再评估人工主导模式新增的响应延迟、目标变化和交接影响。基线比较使用相同机体、载荷和尽可能一致的电池、环境条件；不一致处记录，不能把差异全部归因于程序。

每步同时显示两类独立门槛：**通过条件**（误差、响应及稳定保持时间）和**停止条件**（硬边界、持续超限、反馈失效等）。未达到通过条件但也未触发停止条件时继续观测至阶段时限，不提前判通过；停止条件触发后终止测试推进并执行对应处置，不默认停桨。

输入映射正确与实际响应正确分别判定。必须关联“原始摇杆 → 映射后的程序目标 → 最终 MAVROS 输出 → 实测姿态/角速度”，避免仅测试代码输出与自身期望一致。

参数优化流程固定为：保留基线 → 提出单一问题及预期改善指标 → 落地上锁 → 修改一个相关参数组 → 生成新参数版本 → 重复同一项目 → 比较结果 → 保留或回退。每次重试与每次改参均保留历史，禁止覆盖失败证据。

安全停止门槛与性能目标分开管理。一般调参轮次保持停止门槛不变；确需修改保护门槛时，另建变更记录、说明依据并重新验证相关故障测试，不与控制增益调整混成一轮。

初版重复性最低要求为同一有效配置下同一项目连续三次满足通过条件；任一失败则保留全部结果并查明原因。该次数是流程最低要求，不代表统计可靠性证明，也不替代自由飞行准入。每次飞行前仍重新检查实时输入、环境和接管能力。

## 12. 日志与证据

每次测试保存唯一 session/test ID、代码版本、PX4 固件与相关参数、实际启动参数、RC 标定、机体载荷、电池和环境备注。

连续记录：命令与回执、状态转移、RC 原始输入和映射值、当前目标、最终 MAVROS 输出、飞控目标反馈、姿态/角速度、位置/速度/高度、GNSS/估计状态、数据年龄、推力、模式、保护事件。

ROS bag/结构化事件/摘要和 PX4 ULog 配套；目标输出不等于实际电机响应，总推力限幅不等于单电机硬上限。可用时记录执行器饱和与电池压降，人工视频用于确认离地、漂移和接触等实际现象。

机载记录不依赖 SSH 在线；磁盘不足、录制失败立即显示。起飞前日志不可用则阻塞测试；飞行中录制失败中止测试推进并按正常终止路径处理，不直接停桨。

## 13. 实施顺序与软件验收

1. 提取连接/只读桥接能力，建立独立 EXE、前端、设置和日志；不改旧页面行为。
2. 实现独立命令协议、唯一运行实例和机载控制权状态机，完成软件测试。
3. 实现 RC 标定、人工主导姿态/推力、地面抑制、完全接管及防自动重入。
4. 实现首版逐步测试引导、参数资格、输入到响应记录、结果判定、基线对比和重复性汇总；GPS 仅作观察。
5. 完成首版软件/仿真/拆桨故障验证，再按第 11.2 节首版顺序放行受保护现场项目。人工主导与完全接管验证通过后封存首版基线。
6. 第二阶段实现定位质量准入、程序起飞、位置/速度轨迹、制动保持、降落和降级，并增加 T08—T10 及相关故障测试。贴墙、吸附、翻转继续独立规划。

最低软件测试覆盖（AUTO、程序起飞/移动、位置输出和自动降级专属条目属于第二阶段，不阻塞首版；其余为首版必需）：

- AUTO 状态四根摇杆任意变化不影响目标；独立开关仍可接管。
- ASSISTED_RC 的 RC 过期、越界、错误映射被拒绝；不持续重用旧输入。
- 交接推力不越硬限制；不匹配、超时和反馈丢失有明确结果。
- 原生退出不会被“姿态未稳定”阻塞；退出后没有自动 OFFBOARD 请求。
- 双击/多客户端/重连/旧 session 命令不重复起飞或移动。
- GPS 状态良好而融合位置失效时拒绝自主测试；无 GPS 不应阻止合格姿态协同。
- 地面启用不会发悬停推力或自动爬升；空中不能停止运行时当作中止。
- 位置和姿态输出唯一、互斥；坐标方向与航向跨 ±π 连续性正确。
- 时间倒退、NaN、估计跳变、模式请求拒绝、飞控失联均可识别。
- 旧 EXE 与新 EXE 不竞争飞控输出，共享设置不互相覆盖飞行参数。
- GPS 合格时仍能直接选择人工主导测试；GPS 不合格时只阻塞依赖定位的项目，不强制先启动程序主导。
- 两条方案每步均能显示操作者、操作提示、实际反馈和结果；页面断线时机载记录继续，恢复后重建步骤状态而不重发动作。
- 程序主导测试的非计划降级会冻结原步骤、记录失败/中止、显示实际人工主导状态并引导收尾，不自动变更原方案或判通过。
- 计划内降级验证、重试、缺数据及现场确认具有独立结果语义，依赖项目不会因模糊的“命令已发送”而放行。
