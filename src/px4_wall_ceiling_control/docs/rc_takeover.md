# 一键遥控器平滑接管

适用于当前仍已解锁、处于 OFFBOARD 的吸顶/侧吸控制，包括 ABORT / FAULT。
页面点击 **一键遥控器接管**，或在已加载工作区环境的 ROS 容器终端运行：

```bash
rosrun px4_wall_ceiling_control rc_takeover.py
```

也可直接调用 `rosservice call /attachment/rc_takeover "{}"`。
返回成功仅表示请求被接受。页面接管状态、`/attachment/rc_takeover/status` 和
`/attachment/flight_phase_reason` 显示过程；最终以 `/mavros/state` 为准。

接管流程：

1. 确认输出已启用、飞控已连接/解锁且为 OFFBOARD、急停未生效、姿态和 RC 数据新鲜。
   从 PX4 读取四轴 RC 映射、校准和反向；油门用校准上下限的中点作为中位。
   不以雷达、ABORT 标志或原动作完成标志阻挡请求。
2. 模式管理器等在途模式请求结束后进入 `RC_TAKEOVER`，清除旧吸附意图，禁止自动重新进入 OFFBOARD。
   原输出流持续到管理器确认；仍由原仲裁节点独占 MAVROS 姿态发布。
3. 首帧姿态取接管时实测四元数，推力取最近 0.3 秒内实际发布值。没有新鲜推力起点时拒绝继续过渡。
   姿态按最短四元数路径限速 20°/s，推力变化不超过 0.15/s；单次定时器步长最多 0.05 秒。
   例如 90° 回正至少约 4.5 秒，持续移动摇杆会改变终点。
4. 过渡期间摇杆实时生效：横滚/俯仰各 ±10°、偏航 ±20°/s、油门映射竖直速度 ±0.5 m/s，
   推力采用现有悬停推力及竖直速度比例反馈，并保留原推力上下限。
   过渡累计至少 2 秒，指令与当前摇杆目标差 <2°、实测姿态差 <5°、
   竖直速度差 <0.2 m/s、推力差 <0.02，连续保持 0.5 秒后允许模式交接。
5. 恢复进入 OFFBOARD 前记录的 ALTCTL / POSCTL；管理器若在 OFFBOARD 中才启动，则使用原任务配置模式。
   交接仍要求有效估计器、光流/测距参数恢复确认；POSCTL 还要求水平位置和速度估计有效。
   模式请求失败会保持平滑接管输出并按原重试间隔重试，直到飞控反馈确认。

过渡采用有界 RC 姿态/竖直速度控制，不等同于完整复现 PX4 的 ALTCTL/POSCTL 控制器。
尤其 POSCTL 的摇杆是水平速度请求，切换后的闭环和摇杆尺度由 PX4 决定；不能保证原生模式切换瞬间完全无跳变。
本功能不自动解除机械吸附、不解锁，也不主动进入 OFFBOARD。

接管开始后若 RC、姿态、飞控或管理器反馈失效，或急停生效，立即停止接管输出并锁存失败；
不会重新使用旧吸附指令，也不会在反馈自行恢复后自动继续。此时由飞手切换飞控模式，
OFFBOARD 流丢失后的处理遵循 PX4 已有失效保护配置。重复点击不会重置过渡起点。
飞手主动切换模式或上锁，接管发布立即停止。

## 验证与部署

本地模拟测试覆盖四元数正负等价、近竖直姿态、变化率、时钟异常、摇杆变化、
ABORT 起点、管理器握手、反馈失效锁存、急停和原生模式估计器门控。
真实 ROS 与台架/飞行验证仍需在部署环境完成。

程序变更后的构建必须在树莓派的既有 Docker 容器内执行：

```bash
docker exec ros1_noetic bash -lc 'source /opt/ros/noetic/setup.bash && cd /root/ros_ws && catkin_make'
```

编译后重启基础程序，使输出节点、模式管理器及页面桥接加载同一版本。不要在飞行中重启。
