# 本机贴墙试飞页面

## Windows 最短使用方法

双击版不需要安装 Codex、Python、ROS 或 QGC：

1. 复制发布包中的 `WallConsole.exe` 和 `修改连接设置.cmd` 到新电脑。
2. 首次双击 EXE，填写树莓派 IP、用户名，选择 `password`（密码）或 `key`（密钥），保存。
   密码模式启动时输入密码，密钥模式选择已授权私钥；首次连接核对并确认主机指纹。
3. 浏览器自动打开；以后双击 EXE 即可。需要改连接时双击 `修改连接设置.cmd`。

程序包不含私钥。连接配置及日志保存在 `%LOCALAPPDATA%/WallConsole`。
密码不写入配置或命令行，只供当前本地服务使用；服务重新启动时需重新输入。
密码模式会忽略私钥字段，即使该字段保留默认路径也不影响连接。

若插拔飞控后出现 MAVROS 连接超时，ROS 名单中的 `/mavros` 可能只是已退出进程的残留注册。
桥接服务现在启动前会检测节点是否响应，并在串口没有其他进程占用时重新启动。
各电脑的桥接节点使用独立名称，避免打开第二个页面时使第一个页面失去 ROS 订阅。
需要这两项修复的是树莓派上的桥接脚本，已有 EXE 无需更换；控制算法及现场参数无需改变。
测试时通过页面启动 `wall_console_flight.launch`，不要同时运行旧的
`attachment_terminal_flight.launch` 或旧 `run.sh`，它们的模式与急停配置不同。
启动本机页面不会发送飞行动作，树莓派离线时仍可打开页面。
下面是源码方式及维护细节，双击版使用者无需执行 Python 安装步骤。
开发者安装 `requirements-console.txt` 与 `pyinstaller==6.20.0` 后运行根目录
`Build-WallConsole.ps1`，产物位于 `dist`；打包只包含本机客户端和网页。

页面在 Windows 本机运行，普通浏览器或 Codex 内嵌浏览器打开 `http://127.0.0.1:8787`。
本机后台通过免密 SSH 连接 `pi@192.168.50.66`，在 `ros1_noetic` 容器中启动
ROS 基础程序、发布动作请求、订阅真实反馈。树莓派不开放 HTTP 端口。

## 打开页面

### 固定三路 USB 设备

本台树莓派使用固定插口别名，避免重启或重新插拔改变 `ttyUSB` 顺序：

| 角色 | 页面串口路径 | 当前绑定插口 ID_PATH |
|---|---|---|
| 飞控（原 USB0） | `/dev/serial/by-path/wall-fcu` | `platform-xhci-hcd.1-usb-0:1:1.0` |
| 顶部雷达（原 USB1） | `/dev/serial/by-path/wall-top` | `platform-xhci-hcd.1-usb-0:2:1.0` |
| 前向雷达（原 USB2） | `/dev/serial/by-path/wall-front` | `platform-xhci-hcd.0-usb-0:2:1.0` |

三只转换器没有唯一序列号，因此必须保持设备插在上述各自的 USB 插口；交换插口时需重新确认角色并更新规则。
规则源文件为 `config/udev/99-wall-robot-serial.rules`。只在树莓派主机安装一次：

```bash
sudo install -m 644 /home/pi/ros_ws/src/px4_wall_ceiling_control/config/udev/99-wall-robot-serial.rules /etc/udev/rules.d/99-wall-robot-serial.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=tty --action=change
sudo udevadm settle
ls -l /dev/serial/by-path/wall-*
```

当前 Docker 绑定整个 `/dev`，可直接看到别名。旧页面配置若仍是完整的 USB0/1/2 默认组合，会自动迁移，波特率、悬停推力及试验模式保持原值；显式配置的其他组合不自动修改。
程序不会把 Linux 的 `ttyUSB0` 强制改名，实际编号可以改变，但上述角色路径保持固定。

在 Windows 工作区执行：

```powershell
.\Start-WallConsole.ps1 -NoBrowser
```

然后在 Codex 浏览器打开 `http://127.0.0.1:8787`。不传 `-NoBrowser` 时打开系统浏览器。
启动脚本优先使用本仓库 `.venv-wall-console`，其次 Codex 自带 Python，再查找系统 Python；
也支持普通 Python 3.10+ 与 `-PythonPath`。捆绑运行时可能更新，因此建议独立虚拟环境。

前提：已验证的 SSH 公钥与 known_hosts、树莓派上的 `ros1_noetic` 容器、
`/root/ros_ws/devel/setup.bash`，以及同步到容器工作区的本包源码。
SSH 主机、用户、密钥和本机端口可通过脚本参数修改。

## 换电脑复用

电脑只运行 HTTP 页面和 SSH 客户端，不需要 ROS、MAVROS、雷达驱动或 QGC。
Codex 是打开本机页面和协助调试的入口；同一页面也能用普通浏览器打开。
Windows 使用根目录 `Start-WallConsole.ps1`；macOS/Linux 可用下面的 Python 命令。
验证过的环境为 Windows、Python 3.12、Paramiko 5.0.0。其他操作系统的实机测试尚未执行。

1. 获取同一版本代码。只复制网页 HTML 不够，必须包含启动脚本及整个本包
   `src/px4_wall_ceiling_control`（其中包括 Python 服务、状态模块和 web 目录）。
   本机不用复制 ROS build/devel 或试飞记录。树莓派仍使用已编译的 `/root/ros_ws`；
   更新消息定义后需先在树莓派 `catkin_make`，再在未解锁时重启基础链路。
   拉取前先检查并备份树莓派本地修改，合并保留现场参数，不使用 `git reset --hard`。
   本机和树莓派代码应保持同一版本；仅更新本机不能获得新版远程配置读取逻辑。
2. 有 Codex 捆绑 Python 时可直接使用；否则安装 Python 3.10+，并安装本机依赖：

   ```powershell
   python -m venv .venv-wall-console
   .\.venv-wall-console\Scripts\python.exe -m pip install -r src/px4_wall_ceiling_control/requirements-console.txt
   ```

3. 新电脑接入能访问树莓派的网络，配置该电脑自己的 SSH 密钥，让树莓派管理员授权公钥。
   私钥留在各自电脑。先核对树莓派主机指纹，再通过一次普通 SSH 登录写入 known_hosts；
   本服务拒绝未知／变化的主机指纹，不自动接受。确认能无交互密钥登录，并执行 `docker ps`
   （用户需要已有 Docker 权限）。新电脑更换不需要改飞控参数。
4. 在代码根目录启动，按实际路径修改参数：

   ```powershell
   .\Start-WallConsole.ps1 -NoBrowser -SshHost 192.168.50.66 -SshUser pi `
     -SshKey "$env:USERPROFILE/.ssh/id_ed25519_wallrobot" `
     -KnownHosts "$env:USERPROFILE/.ssh/known_hosts" -SshPort 22 `
     -Container ros1_noetic -RemoteWorkspace /root/ros_ws
   ```

   普通 Python 可以额外指定 `-PythonPath 'C:/Python312/python.exe'`。
   HTTP 端口占用时用 `-Port 8791`，对应打开 `http://127.0.0.1:8791/`。
   脚本不会把另一台 SSH 目标的既有页面误认成当前连接。

   macOS/Linux 或直接运行 Python：

   ```bash
   python3 src/px4_wall_ceiling_control/scripts/operator/wall_console_server.py \
     --ssh-host 192.168.50.66 --ssh-user pi --ssh-port 22 \
     --ssh-key "$HOME/.ssh/id_ed25519_wallrobot" --known-hosts "$HOME/.ssh/known_hosts" \
     --container ros1_noetic --remote-workspace /root/ros_ws --port 8787
   ```

5. 打开本机地址，先确认 SSH 连接和反馈。若飞机已有基础链路运行，新电脑读取树莓派上
   的实际串口、波特率、推力和台架配置，不用本机默认值覆盖它们，不重复启动控制节点。
   尚未启动时，由操作者选择“有约束台架”并核对三路串口／推力；新电脑配置文件初始默认
   为“普通实飞”，不能仅因电脑换了就假定台架限制已关闭。
6. 静态、未解锁时验收基础程序和传感器。之后由飞手按既有流程起飞、贴墙、离墙、
   确认 ALTCTL、降油门落地／承托、上锁。急停收尾后，解除急停并保持有效 RC 反馈，
   等待 IDLE、owner=0、ALTCTL，再由飞手重新解锁。页面不自动解锁或重放上次命令。

不要同时用两台电脑发动作；更换操作电脑时先停止旧本机 HTTP 后台，树莓派飞行程序保持运行。
关闭页面／SSH 不会终止飞行程序。配置路径可用 `-Settings` 或 `--settings` 指定。
断电或 USB 掉线需要先恢复硬件；ROS 节点名残留不代表 MAVROS 进程和串口仍有效。
上次测试已验证接管和急停后的重新待命，但 USB 设备随后消失，所以尚未完成第二轮实飞。

验收顺序：全新配置启动 → SSH 反馈 → 读取现场配置 → 重复启动不产生新节点 →
SSH 断开时按钮禁用／重连不重放 → 现场完成一轮 → 解除急停后第二轮。
软件回放不能替代最后两步的实机验收。

## TELEM2 串口配置

2026-10-02 现场三线 TX/RX/GND 接法：通过飞控 USB 读回并设置
`MAV_1_FLOW_CTRL=0`、`SER_TEL2_BAUD=230400`，重启飞控后生效。
保留 `MAV_1_CONFIG=102`、`MAV_1_MODE=2`、`MAV_1_RATE=0`。
飞控端和 MAVROS 端波特率必须一致。页面只配置 MAVROS，不自动写飞控参数或重启飞控。

实测 921600 约 48% 接收帧 CRC 失败；关闭流控仍约 46%，460800 仍约 23%。
230400 首轮 20 秒 4444 帧未出现 CRC 失败，心跳最大间隔约 1.02 秒。
这表明当前链路高速通信异常，尚不能仅凭 Linux `ch341` 驱动名称确认芯片型号或模块故障。

降速后 PX4 会按带宽缩减消息频率。启动入口在确认未解锁后，经
`/mavros/set_message_interval` 请求 `ESTIMATOR_STATUS`（消息 230）5 Hz，
实际收到约 2 Hz；该请求在飞控重启后需重新执行。桥接监测会在飞控／SSH
重新连接后，确认状态新鲜且未解锁时自动恢复请求；估计器状态再次过期时也会
自动重试，两次请求至少间隔 10 秒。无需电脑 USB 直连或打开 QGC。
已解锁时不更改遥测设置；频率不足导致动作被锁止后，需先由飞手着陆上锁。
保持原有 1.5 秒估计器有效期，不通过放宽阈值掩盖缺失反馈。

## 页面反馈与限制

贴墙保持为本轮里程碑：进入 `WALL_HOLD` 后，记录和已达阶段保留到下一次贴墙
请求被控制节点接受。中止、离墙、反馈中断仍显示当前情况，不把历史成功当作当前保持。
里程碑随控制节点状态发布，页面刷新或 SSH 重连可以恢复；控制节点重新启动会清空本轮记录。

一键离墙发送同一终端链路的 `detach` 指令。仅当前 `WALL_HOLD`、已解锁 OFFBOARD、
贴墙输出有效且急停未触发时接受请求；顶部雷达、里程计、估计器和急停反馈
过期会禁用。控制节点保持贴墙，等待姿态／角速度连续稳定后旋转，8 秒未满足自动取消请求。
有约束台架关闭离墙入口的垂直速度幅值门槛，但要求反馈有限，并保留姿态、角速度和雷达检查。
普通实飞保留 ±0.15 m/s 门槛。发送后等待 `DETACH_ROTATE → RECOVER → EXIT/IDLE → RETURNING → ALTCTL`，
按钮不自动重发。有约束台架的离墙旋转、恢复和交接不依赖顶部雷达，也不使用估计高度
偏差或垂直速度幅值作为完成门槛／推力修正；反馈仍必须有限，姿态、角速度、通信与急停保护保留。
普通实飞保留雷达与高度／速度检查。正常恢复或 ABORT 恢复到水平后，在 EXIT 保留水平输出，
管理程序进入 RETURNING，等待姿态在 10° 内、各轴角速度不超过 0.3 rad/s 与有效连续输出，
请求 ALTCTL 并等待飞控确认，再释放输出。异常历史保留，异常恢复不会伪装成正常离墙完成。
飞手确认已交还遥控后降低油门落地，再按正常流程上锁；程序不会自动停机。

急停配置通过 MAVROS 读取飞控 `RC_MAP_KILL_SW`、`RC_KILLSWITCH_TH` 与对应通道
MIN/MAX/REV，不猜测通道。专用入口启用急停保护；终端节点发布 `/attachment/kill_switch`，
页面记录通道、触发与反馈有效状态，ROS bag 同步记录。急停立即清除终端动作请求、
禁止模式切换与设定值输出，不等待 `armed=false`；解除急停不会恢复旧请求。

测试配置可选择 **普通实飞** 或 **有约束台架**（允许离地，现场有机械／绳约束）。
台架配置关闭最低高度入口门槛，并允许两路雷达暂时无效时发起 OFFBOARD 交接；
此时 wall 决策保持中立悬停，等待两路真实有效距离后才进入接近阶段。
台架接近阶段若任一路距离无效，暂停接近并保持中立悬停，清除翻转距离计时，
距离恢复后再继续；不因弱反射直接 ABORT，也不凭历史无效距离触发翻转。
进入翻转后前向雷达不参与安全判断；离墙旋转、恢复与交接阶段两路雷达均不参与。
雷达无法区分墙面和走入光路的人，有效但被遮挡的读数仍可能影响接近／接触判定。
接近、翻转、接触判定仍使用有效雷达；保留解锁、ALTCTL 发起、心跳／里程计／估计器
有效性、角速度、下沉速度、输出与接管保护。该配置不会自动解锁或起飞。
页面显示台架配置、每项阻塞原因及 E255/E258 诊断，雷达异常在台架入口仅提示。

普通实飞最低高度现使用解锁前最后一帧新鲜地面 ENU z，解锁时冻结参考，
计算 `当前位置 z - 解锁地面 z`。飞行中不自动重置；如果节点在空中启动或解锁前
地面数据过期，则不建立参考，普通实飞入口保持阻塞。台架取消高度门槛但仍显示该测量。

- SSH、飞控连接、解锁、实际模式、输出 owner、控制阶段和原始故障原因。
- 两路有效距离、实测横滚/俯仰、ENU 竖直速度、电池电压。
- 真正发布到 `/mavros/setpoint_raw/attitude` 的推力；不把候选值或飞控回传当作已发送值。
- 心跳、里程计、估计器、RC、雷达和贴墙状态的数据年龄。超过现有控制链路的阈值会标为过期，
  不使用历史值确认成功。页面的就绪检查不是完整飞行资格认证，飞手判断稳定后再点击。
- 操作回执表示发送完成；订阅的控制状态表示节点确认与执行进展。

启动幂等，不同时创建两个 MAVROS/控制链路。原有其他控制入口仍在运行时显示冲突，
不会自动结束它们或抢占串口。配置变更不支持在线重启控制链路。
切换旧启动入口时，应在飞控未解锁状态用 Ctrl+C 结束整个旧 roslaunch，不能只结束
ROS master：残留节点可能不再出现在节点列表中，却仍持有雷达串口。
页面启动在确认飞控未解锁后，检查两路雷达没有其他串口读取进程，再发送一次
`iHALT` 结束此前的测量，新雷达节点用 `iACM` 重新启动；避免热启动时返回 `BUSY`
而没有有效距离。重复点击已运行的基础程序不复位雷达，运行中也不自动复位。
页面关闭、后台退出或 SSH 中断不会主动关闭已经启动的飞行进程，避免网络故障改变控制输出。
SSH 恢复只恢复订阅。程序退出后页面会取消就绪状态，并显示缺失节点。
本页面没有解锁、停机、模式强切或“急停”按钮；结束测试仍由飞手按原流程接管。

树莓派容器中的启动日志位于 `/root/.ros/wall_console/`；自动试飞记录仍在
`/root/wall_test_records/`。本机服务日志在 `%LOCALAPPDATA%/WallConsole/`。

## 验证

核心状态检查可在无 ROS 的 Python 环境运行：

```bash
python3 -m unittest discover -s src/px4_wall_ceiling_control/test -p test_wall_console.py
```

前端测试使用模拟 HTTP 反馈验证未就绪、就绪、请求回执、贴墙确认、故障和 SSH 中断。
真实 SSH/ROS 连接验证不发送贴墙请求或启动飞行控制；实际离地和贴墙必须现场测试。

## 多电脑共享反馈

Windows EXE 经 SSH 启动轻量 relay，容器内 `--shared-service` 用文件锁确保单实例，唯一 RemoteRuntime 订阅 ROS 并统一生成 10 Hz 快照。Unix socket 位于 `~/.ros/wall_console/shared.sock`，权限 0600，不暴露公网端口。无客户端时服务仍观察并记录事件；不停止飞行节点。日志 `~/.ros/wall_console/shared-service.log`。容器重启后首次连接自动启动。

默认各电脑为观察端，显式申请控制权；树莓派在同一锁内验证控制权和分发动作。没有自动抢占。暂停推送保留 SSH 和控制权，禁用本机动作；其他电脑不受影响。断线保留 30 秒，同一客户端进程重连恢复，超时后新申请仅在有效未解锁状态或确认已交回 ALTCTL 时接受。冷启动无 MAVROS 时可申请控制权以启动基础程序。关闭浏览器不会退出本地服务。旧客户端不支持新握手，升级需要所有电脑替换 EXE 并重启本地服务。

部署遵循本机提交 → Gitee 推送 → 树莓派 git pull --ff-only。不要直接覆盖树莓派脚本。服务代码升级仅在确认飞控未解锁时重启桥接，不重启飞行节点。

## 重置本轮观测

“重置本轮观测”只清空当前浏览器的历史进度高亮、历史成功提示和旧显示记录，并保存在本机浏览器。刷新不会带回旧进度；下一轮 WAITING_WALL／PRESTREAM／FRONT_WALL_DETECT 到来后正常跟踪新一轮。飞行动作执行时禁用；断线后也可重置显示，但不会把旧反馈当作实时反馈重新启用动作。该操作没有 ROS／SSH 动作请求，不清理控制器状态、不删除树莓派日志，不影响其他电脑的观察。

## 飞手手动接近入口

`wall_console_flight.launch` 为模式管理器启用 `wall_manual_approach=true`，并为决策节点启用 `manual_approach=true`。发送 wall 后进入 WAITING_WALL，保持 ALTCTL，同时开启 OFFBOARD 预发送，不申请贴墙输出归属。使用决策节点同一前向滤波距离和连续采样计时判定翻转条件：当前 ≤0.20 m、连续0.30 s；同时要求新鲜两路有效距离和原有交接前置条件。无额外3秒准备延时。

`flight_mode_manager_node/manual_wall_wait_timeout_s=60.0` 是请求后的最大手动等待时间；包括距离条件反复失效后的等待，不重复延长。手动接近期间并行建立默认1.5秒连续预发送，在 ALTCTL 下仍由飞手操控。距离条件满足且预发送已就绪，即请求 OFFBOARD，不再额外等待1.5秒。距离条件反复变化不重置预发送计时；控制目标流中断则重新计时。飞控确认 OFFBOARD 后跳过3°自动接近，直接进入 FLIP_TO_WALL 并申请输出归属。确认接管时距离条件丢失则进入交回 ALTCTL 的路径。

“取消等待”使用专用 `/wall_perch/cancel_wait`，模式管理器只在 WAITING_WALL 接受；晚到的消息不打断接管／翻转。超时释放终端意图，不请求 OFFBOARD。原 `approach_timeout_s=20` 只用于保留的自动接近入口；`flip_time_s=2` 翻转耗时、`capture_timeout_s=8` 接触确认超时不变。其他旧入口默认维持自动接近。

### 翻转初段推力衔接

页面入口启用 `match_fcu_thrust_on_handover=true`，预发送匹配新鲜的 PX4 ATTITUDE_TARGET 推力；首次接管保持捕获值，随后用1秒平滑曲线衔接到行为推力。未解锁启动时请求 ATTITUDE_TARGET 10 Hz，反馈缺失或过期时不生成匹配预发送，不能跳过此确认直接接管。

现场实际 ATTITUDE_TARGET 约4 Hz、间隔0.25秒，因此页面入口将该推力来源反馈有效期设为0.35秒；超过0.35秒仍停止匹配预发送。此值仅用于接管推力来源，不改变飞控心跳、姿态、控制输出或角速度保护有效期。

### 台架贴墙阶段的短时雷达异常

有约束台架的翻转、接触确认、保持及压墙阶段，不再因顶部雷达一帧错误立即退出：仅当最近有效距离仍在原0.6秒有效期内，且传感器健康反馈仍新鲜时允许继续。异常帧不更新时间戳；持续无有效距离超过0.6秒或健康反馈过期仍触发恢复。接管前仍要求两路健康标志有效。异常帧会清空接触连续确认计时，恢复有效测距后重新确认，不能以异常帧判定贴墙成功。普通实飞入口维持原健康标志要求，急停、姿态、角速度和飞控保护不变。

### 临时离墙参数调整（2026-10-04）

按台架观察到的掉高现象，先将 `detach_time_s` 从4.0改为3.0秒、`detach_compensation_start_deg` 从75改为80度：机身从竖直转平时更早开始竖直推力补偿，缩短支撑不足阶段。参数文件也适用于其他读取它的入口，属于临时试验值；回退为4.0秒和75度即可。悬停推力0.45、贴墙倍率、推力上限0.85、1秒恢复阶段及原有保护不变。台架推力补偿只根据实测姿态和悬停推力，不使用局部高度误差或竖直速度误差调推力。此调整不能保证保持高度，切回 ALTCTL 后的下降仍受飞控和飞手油门输入影响。

针对转平后仍掉高，新增 `bench_detach_hover_thrust=0.48`，只作用于有约束台架离墙及恢复的竖直支撑补偿，并在 EXIT 等待交还期间继续保持，不再回落至0.45。贴墙、翻转和普通实飞的悬停参数仍为0.45。该临时值依据原有悬停配置小幅提高，尚未标定；回退为0.45即可。ALTCTL 确认后输出归属释放，后续推力由飞控和飞手输入决定。

同时启用 `flip_thrust_follow_tilt=true`：翻转额外推力随实测机体推力轴相对竖直方向的倾角，经五次平滑曲线增加；水平时为悬停推力，90°时达到原翻转倍率。以0.45、1.35为例，水平为0.45、45°为0.52875、90°为0.6075；航向转动不会增加推力。目标姿态仍采用2秒翻转曲线，角速度及其他保护保留。旧入口默认保留原固定翻转推力。本改动需台架实测验证，不代表已确认实际爬升消除。
# 台架测距超时

有约束台架启动时，测距健康节点的 `input_timeout_s` 和贴墙决策节点的
`sensor_timeout_s` 统一覆盖为 1.2 秒，用于容忍约 1.1 秒的有效测距间断。
超过 1.2 秒仍会阻止动作或触发恢复。普通实飞沿用 YAML 中的 0.6 秒。
飞控、传感器健康消息的心跳超时及姿态保护不变；贴墙确认仍需有效样本更新，
缓存样本不会独自推进确认时间，无效顶部样本仍重置连续确认。

## 台架离墙控制

台架离墙恢复时间曲线：从离墙瞬间实测姿态，以5秒五次平滑插值转向已保存的水平姿态。
台架入口固定 `detach_time_s=5.0`，只影响目标姿态推进；时间到不代表机体已转平，也不按时间报失败。
实际姿态进入原有 15 度恢复范围、各轴角速度不超过恢复限制后才进入 RECOVER，
随后保留原有稳定检查和 ALTCTL 交接。进度来自实际倾角，卡在墙上不会显示旋转完成。
总推力从当时贴墙输出按每秒 0.45 的变化上限过渡，实际竖直时目标为当前悬浮基准
（默认 0.45），随实际姿态转平平滑接到 0.48；不使用除余弦补偿。
这些值是台架临时调节值，仍需验证支撑力与旋转响应。普通实飞保留原离墙轨迹。
台架翻转与 WALL_CAPTURE 仅俯仰角速度上限为 9 rad/s，其余轴和恢复阶段限制不变。
模式管理节点在独立线程、飞控新鲜连接且未解锁时请求 SERVO_OUTPUT_RAW 10 Hz，
并在未解锁时周期重试以覆盖重启。原始 `/mavros/rc/out` 已纳入 rosbag；
请求确认不等于收到电机输出，也不代表真实转速或推力反馈。
